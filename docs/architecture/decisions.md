# Decisiones técnicas para revisar en código

Estas son justificaciones actuales basadas en la implementación. Los antecedentes históricos se conservan en los ADR; no se atribuyen motivos no registrados.

| Decisión | Problema y solución | Alternativa y coste | Código / prueba |
| --- | --- | --- | --- |
| Aislamiento explícito | Un ID válido no demuestra pertenencia. Consultas por empresa, policies y FKs compuestas protegen acceso y referencias | Un global scope podría centralizar filtros, pero requeriría controlar escapes y contexto de jobs. La estrategia actual exige disciplina en cada consulta | [DraftDocuments](../../backend/app/Actions/Documents/DraftDocuments.php), [DraftDocumentsTest](../../backend/tests/Feature/DraftDocumentsTest.php) |
| Dinero entero | `float` introduce errores binarios. Importes en centavos, cantidades en milésimas y redondeo definido | Decimal arbitrario también es viable. Los enteros requieren límites explícitos y conversiones estrictas en API/proveedor | [Money](../../backend/app/Domain/Money/Money.php), [TaxCalculator](../../backend/app/Domain/Money/TaxCalculator.php), [MoneyTest](../../backend/tests/Unit/MoneyTest.php), [ADR-018](../adr/ADR-018-importes-y-borradores.md) |
| Número y cuota transaccionales | Dos emisiones pueden competir por el mismo correlativo o último cupo. Bloqueos y commit coordinan número, consumo y solicitud | Un contador externo separaría el estado y dificultaría rollback. Bloquear filas introduce contención por empresa/serie, sin afirmar rendimiento no medido | [RequestIssuance](../../backend/app/Actions/Issuance/RequestIssuance.php), [Subscriptions](../../backend/app/Actions/Subscriptions/Subscriptions.php), [concurrencia](../../backend/tests/Concurrency/subscriptions.php), [ADR-016](../adr/ADR-016-series-y-correlativos-transaccionales.md) |
| Idempotencia y outbox | Una respuesta perdida o Redis caído no debe duplicar efectos ni perder el trabajo confirmado. Se guardan clave, huella y outbox en PostgreSQL | Publicar directamente después del commit deja una ventana de pérdida. El outbox agrega tablas, publisher y mantenimiento | [EmissionOutbox](../../backend/app/Actions/Issuance/EmissionOutbox.php), [IssuanceTest](../../backend/tests/Feature/IssuanceTest.php), [Redis real](../../scripts/test-integral-recovery.cjs) |
| Resultado incierto y conciliación | Un timeout puede ocurrir después de aceptar un pago o envío. Se consulta la identidad persistida, se valida al proveedor y se limita el reintento | Reenviar a ciegas simplifica código pero puede repetir efectos. La solución requiere leases, estados de revisión y operación manual para ciertos casos | [ProcessEmission](../../backend/app/Actions/Issuance/ProcessEmission.php), [PaymentWork](../../backend/app/Actions/Payments/PaymentWork.php), [CollectionsTest](../../backend/tests/Feature/CollectionsTest.php), [ADR-019](../adr/ADR-019-cobranza-mercado-pago-sandbox.md) |

Las notas 07 conservan una referencia a cada línea histórica. Un índice único parcial de PostgreSQL protege las líneas reservadas o acreditadas. La numeración, cuota y reserva comparten transacción. [Implementación](../../backend/app/Actions/Documents/CreditNotes.php).
